CUEBRACKET PRO — PASSWORD RESET PATCH
=====================================

PATCH CONTENTS
--------------
components/AuthForm.tsx
components/ForgotPasswordForm.tsx
components/UpdatePasswordForm.tsx
app/auth/forgot-password/page.tsx
app/auth/update-password/page.tsx

WHAT THIS ADDS
--------------
1. "Forgot password?" link on the existing sign-in form.
2. /auth/forgot-password page.
3. Supabase password reset email using resetPasswordForEmail().
4. Reset email returns through your existing:
      /auth/callback?next=/auth/update-password
5. /auth/update-password page.
6. New-password + confirm-password validation.
7. Supabase updateUser({ password }) password change.
8. Invalid/expired reset-link handling.
9. Automatic return to /dashboard after a successful password change.

HOW TO APPLY
------------
1. Close your CueBracket dev server if it is running.
2. Extract this ZIP.
3. Copy/extract its contents directly into:
      C:\project\cuebracket
4. Allow Windows to REPLACE components\AuthForm.tsx.
5. The other four .tsx files are new.
6. Open terminal in C:\project\cuebracket and run:
      npm run build
7. If the build passes:
      git add .
      git commit -m "Add forgot password and password reset flow"
      git push

SUPABASE NOTE
-------------
This patch deliberately reuses your EXISTING /auth/callback route. Your signup
flow already uses that callback, so you normally should not need a new callback
route.

For production, NEXT_PUBLIC_SITE_URL should point to your production CueBracket
URL, for example:
      https://cuebracket-doaa.vercel.app

TEST
----
1. Open /auth/login.
2. Confirm "Forgot password?" appears beside Password.
3. Click it.
4. Enter an existing organizer email.
5. Check inbox/spam for the Supabase reset email.
6. Click the reset link.
7. CueBracket should open /auth/update-password.
8. Enter the new password twice.
9. Submit.
10. You should return to /dashboard.

IMPORTANT
---------
Supabase's default email service is rate-limited. If a reset email does not
arrive during repeated tests, check Supabase Auth logs/rate limits and spam.
For a production app, configure custom SMTP when you are ready.
